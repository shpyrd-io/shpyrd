The **+** on the launcher is now a menu: an empty project, a project from GitHub, or one **from templates**. A template is an application ready to run on shpyrd: pick one, give it what it asks, and it becomes a project of yours, built from its repository and following it from then on, so a new commit on its branch is released like any push of your own. Pin a tag instead to stay on a version.

The first templates are agents. **Fluxyr**, a Python framework for agents with its own web UI, asks for an OpenRouter key and a model. **Hermes Agent**, Nous Research's agent, asks for nothing at install: the first visit shows a short setup, the provider, the key and the model chosen from what the provider offers, and then the address is Hermes' dashboard. Telegram, Discord and the other channels are connected afterwards, from the dashboard or a shell on the project. Both keep their state on a disk of the project, and the platform's sign-in stands in front of them.

From the terminal: `shpyrd catalog list`, `shpyrd catalog show <entry>`, `shpyrd catalog install <entry> --input NAME=value`. See [the catalog](/docs/deploying#from-the-catalog) and [the launcher](/docs/dashboard#the-catalog).

Templates live in a public repository, [shpyrd-io/catalog](https://github.com/shpyrd-io/catalog): a folder with the project's own `shpyrd.yaml`, a `catalog` block saying what it is and what it asks, and any files to lay over the upstream code, a Dockerfile for example. A pull request there is how an application joins the list; `shpyrd catalog validate` says what is missing. Servers read the published index on their own, so a new template needs no update of the platform.
